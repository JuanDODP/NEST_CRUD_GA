Tablas del Sistema

T-01

users  ·  Usuarios del Sistema

dbo.users
📌 Almacena las credenciales, datos personales y configuración de acceso de cada usuario registrado en el sistema. El campo password se encripta con bcrypt (10 rounds) antes de persistir. El campo rol se guarda como cadena simple dado que SQL Server no admite arrays nativos.
Columna Tipo SQL Server Longitud / Precisión Nulable Valor por Defecto Restricciones Descripción
id INT — NO IDENTITY(1,1) PK Identificador único autoincremental del usuario.
name NVARCHAR(255) 255 chars NO — — Nombre completo del usuario. Soporta caracteres Unicode (acentos, ñ).
email NVARCHAR(255) 255 chars NO — UNIQUE Correo electrónico. Normalizado a minúsculas en @BeforeInsert / @BeforeUpdate. Índice único en la tabla.
password NVARCHAR(MAX) Sin límite NO — select: false Hash bcrypt de la contraseña (10 rounds). Excluido de las consultas SELECT por defecto para seguridad.
rol NVARCHAR(255) 255 chars NO 'user' — Rol del usuario en el sistema. Valores posibles: user, admin. No usa array ya que SQL Server no soporta tipos de arreglo nativos.
imagen NVARCHAR(255) 255 chars NO 'default-avatar-user.jpg' — Nombre del archivo de imagen del avatar. La URL completa se construye dinámicamente con HOST_API mediante @AfterLoad. Al actualizar, el archivo anterior se elimina físicamente del disco (fs.unlinkSync), excepto si es default-avatar-user.jpg.
salary DECIMAL(18,2) Precisión 18, Escala 2 NO 0.00 — Sueldo del usuario en moneda local. Máximo 2 decimales, mínimo 0. Validado con @IsNumber({ maxDecimalPlaces: 2 }) y @Min(0).
isActive BIT 0 ó 1 NO 1 — Indica si el usuario está activo (1) o ha sido desactivado lógicamente (0). SQL Server usa el tipo BIT para booleanos.
fechaRegistro DATETIME2 Hasta 7 decimales NO GETDATE() @CreateDateColumn Fecha y hora exacta del registro del usuario. Gestionado automáticamente por TypeORM en el momento de la inserción.
T-02

areas  ·  Áreas Organizacionales

dbo.areas
📌 Define las áreas funcionales o departamentales de la empresa. Cada área puede tener múltiples proyectos asociados. Incluye exportación de datos a Excel mediante ExcelJS y generación de reportes administrativos.
Columna Tipo SQL Server Longitud / Precisión Nulable Valor por Defecto Restricciones Descripción
id INT — NO IDENTITY(1,1) PK Identificador único autoincremental del área.
nombre NVARCHAR(255) 255 chars NO — — Nombre descriptivo del área (ej: "Recursos Humanos", "Sistemas"). Longitud definida para optimizar índices en SQL Server.
description NVARCHAR(MAX) Sin límite NO — — Descripción detallada del área. Se usa NVARCHAR(MAX) en lugar de TEXT (deprecado en SQL Server moderno) para descripciones largas.
imagen NVARCHAR(255) 255 chars NO 'default-image.png' — Nombre del archivo de imagen representativa del área. La URL se construye dinámicamente mediante @AfterLoad con la variable HOST_API. Al actualizar la imagen, el archivo anterior se elimina del sistema de archivos.
T-03

proyectos  ·  Proyectos

dbo.proyectos
📌 Registra los proyectos de la organización vinculados a un área específica. Define el ciclo de vida del proyecto mediante fechas de inicio y fin. Cuenta con exportación a Excel con datos enriquecidos (nombre del área, descripción) mediante una consulta con relaciones.
Columna Tipo SQL Server Longitud / Precisión Nulable Valor por Defecto Restricciones Descripción
id INT — NO IDENTITY(1,1) PK Identificador único autoincremental del proyecto.
nombreProyecto NVARCHAR(255) 255 chars (mín. 3) NO — — Nombre del proyecto. Validado con longitud mínima de 3 caracteres mediante @MinLength(3) en el DTO.
fechaInicio DATETIME2 Alta precisión NO — — Fecha de inicio del proyecto. Se usa DATETIME2 (en lugar de DATE) para mayor precisión y compatibilidad con strings ISO 8601. Validado con @IsISO8601 en el DTO.
fechaFin DATETIME2 Alta precisión NO — — Fecha estimada de finalización del proyecto. Debe ser posterior a fechaInicio (integridad lógica validada en el DTO de creación).
imagen NVARCHAR(255) 255 chars NO 'default-image.png' — Nombre del archivo de imagen del proyecto. La URL completa se construye con HOST_API en tiempo de consulta (@AfterLoad). La imagen se guarda en static/proyectos/.
areaId INT — SÍ NULL FK → areas.id Clave foránea que vincula el proyecto con su área organizacional. Generada por TypeORM mediante @ManyToOne / @JoinColumn({ name: 'areaId' }). Error 547 si se intenta eliminar un área con proyectos activos.
T-04

asignaciones  ·  Asignaciones

dbo.asignaciones
📌 Tabla pivote que establece la relación muchos-a-muchos entre usuarios y proyectos. Registra la fecha exacta de asignación. Soporta generación de reportes PDF individuales por asignación (con datos del usuario, proyecto y área), usando PDFKit con imágenes locales del servidor.
Columna Tipo SQL Server Longitud / Precisión Nulable Valor por Defecto Restricciones Descripción
id INT — NO IDENTITY(1,1) PK Identificador único autoincremental de la asignación.
fechaAsignacion DATETIME2 Alta precisión NO — — Fecha y hora en que se realizó la asignación del usuario al proyecto. Validado con @IsISO8601 en el DTO. Usado en reportes PDF con formato localizado (es-MX).
idUsuario INT — SÍ NULL FK → users.id Clave foránea al usuario asignado. Generada mediante @ManyToOne(() => User) y @JoinColumn({ name: 'idUsuario' }). El campo password del usuario se omite en las respuestas de consulta.
idProyecto INT — SÍ NULL FK → proyectos.id Clave foránea al proyecto asignado. Generada mediante @ManyToOne(() => Proyecto) y @JoinColumn({ name: 'idProyecto' }). Error 547 si se intenta eliminar un proyecto con asignaciones activas.

Tablas Propuestas  — Extensión del modelo de datos

T-05

departamentos  ·  DepartamentosPropuesta

dbo.departamentos
💡 Justificación: El modelo actual no cuenta con una jerarquía organizacional superior a las áreas. Esta tabla permite agrupar múltiples áreas bajo un mismo departamento (ej: Tecnología → Área de Sistemas, Área de QA), reflejando la estructura corporativa real de INTEGRA ARRENDA. Permite también controlar un presupuesto a nivel de departamento y asignar un responsable titular.
Columna Tipo SQL Server Longitud / Precisión Nulable Valor por Defecto Restricciones Descripción
id INT — NO IDENTITY(1,1) PK Identificador único autoincremental del departamento.
nombre NVARCHAR(255) 255 chars NO — — Nombre oficial del departamento (ej: "Tecnología e Innovación", "Administración y Finanzas").
codigo NVARCHAR(20) 20 chars NO — UNIQUE Código interno único del departamento (ej: DEPT-TI-001). Útil para referencias cruzadas en reportes y exportaciones.
responsable NVARCHAR(255) 255 chars SÍ NULL — Nombre del titular o jefe del departamento. Campo de texto libre para mayor flexibilidad (sin FK directa al inicio).
presupuesto DECIMAL(18,2) Precisión 18, Escala 2 NO 0.00 — Presupuesto anual asignado al departamento. Tipado con DECIMAL(18,2) siguiendo la directiva de tipado monetario estricto del proyecto.
descripcion NVARCHAR(MAX) Sin límite SÍ NULL — Descripción extendida de las funciones y responsabilidades del departamento.
isActive BIT 0 ó 1 NO 1 — Estado del departamento. Permite desactivación lógica sin eliminación física del registro, manteniendo integridad referencial con las áreas vinculadas.
fechaCreacion DATETIME2 Alta precisión NO GETDATE() @CreateDateColumn Fecha y hora de creación del registro. Gestionado automáticamente por TypeORM.
T-06

contratos  ·  Contratos LaboralesPropuesta

dbo.contratos
💡 Justificación: El modelo actual solo almacena el salario actual del usuario, pero no tiene trazabilidad de sus condiciones contractuales históricas. Esta tabla permite asociar uno o más contratos a cada usuario, registrando el tipo de relación laboral, las fechas de vigencia, el salario base pactado y el estado del contrato. Es especialmente útil para el módulo de reportes y auditorías de INTEGRA ARRENDA.
Columna Tipo SQL Server Longitud / Precisión Nulable Valor por Defecto Restricciones Descripción
id INT — NO IDENTITY(1,1) PK Identificador único autoincremental del contrato.
tipoContrato NVARCHAR(100) 100 chars NO — — Clasificación del contrato. Valores esperados: INDEFINIDO, TEMPORAL, HONORARIOS, PROYECTO. Se recomienda validar con enum en el DTO.
fechaInicio DATETIME2 Alta precisión NO — — Fecha de inicio de vigencia del contrato. Debe ser anterior o igual a fechaVencimiento.
fechaVencimiento DATETIME2 Alta precisión SÍ NULL — Fecha de vencimiento del contrato. NULL para contratos indefinidos activos. Permite alertas programadas de vencimiento próximo.
salarioBase DECIMAL(18,2) Precisión 18, Escala 2 NO 0.00 — Salario base pactado en este contrato específico. Histórico independiente del campo salary en la tabla users, que refleja el salario vigente actual.
estado NVARCHAR(50) 50 chars NO 'ACTIVO' — Estado actual del contrato. Valores posibles: ACTIVO, VENCIDO, CANCELADO, RENOVADO. Permite filtrar contratos vigentes en reportes.
observaciones NVARCHAR(MAX) Sin límite SÍ NULL — Notas o comentarios adicionales sobre cláusulas especiales, modificaciones o condiciones particulares del contrato.
idUsuario INT — SÍ NULL FK → users.id Clave foránea al usuario titular del contrato. Relación ManyToOne con la entidad User. Un usuario puede tener múltiples contratos a lo largo del tiempo (histórico).
fechaRegistro DATETIME2 Alta precisión NO GETDATE() @CreateDateColumn Fecha y hora en que se registró el contrato en el sistema. Auditoria básica de creación del registro.
T-07

auditoria_log  ·  Log de AuditoríaPropuesta

dbo.auditoria_log
💡 Justificación: El sistema no cuenta con trazabilidad de cambios sobre entidades críticas. Esta tabla registra automáticamente qué usuario realizó qué acción, sobre qué entidad, cuándo y desde qué IP. Es fundamental para cumplimiento normativo, auditorías internas y detección de anomalías. Se recomienda poblarla mediante interceptores NestJS (@UseInterceptors) o subscribers de TypeORM (EntitySubscriberInterface).
Columna Tipo SQL Server Longitud / Precisión Nulable Valor por Defecto Restricciones Descripción
id BIGINT — NO IDENTITY(1,1) PK Identificador único de la entrada de log. Se usa BIGINT (en lugar de INT) previendo un alto volumen de registros a largo plazo.
accion NVARCHAR(50) 50 chars NO — — Tipo de operación registrada. Valores posibles: CREATE, UPDATE, DELETE, LOGIN, LOGOUT, EXPORT. Permite filtrar por tipo de evento en reportes.
entidad NVARCHAR(100) 100 chars NO — — Nombre de la tabla o entidad afectada por la acción (ej: users, proyectos, asignaciones). Permite filtrar el log por entidad específica.
entidadId INT — SÍ NULL — ID del registro afectado dentro de la entidad indicada. NULL para acciones globales (ej: exportaciones, inicio de sesión).
valorAnterior NVARCHAR(MAX) Sin límite SÍ NULL — Snapshot en JSON del estado del registro antes del cambio. NULL en operaciones de creación. Permite comparación diff entre estados.
valorNuevo NVARCHAR(MAX) Sin límite SÍ NULL — Snapshot en JSON del estado del registro después del cambio. NULL en operaciones de eliminación.
ipOrigen NVARCHAR(45) 45 chars SÍ NULL — Dirección IP desde la que se originó la petición HTTP. 45 caracteres soporta tanto IPv4 (xxx.xxx.xxx.xxx) como IPv6 completo. Extraída del objeto Request en el interceptor.
userAgent NVARCHAR(500) 500 chars SÍ NULL — Cadena User-Agent del cliente que realizó la petición (navegador, sistema operativo, versión). Útil para detectar patrones de acceso inusuales o bots.
fechaEvento DATETIME2 Alta precisión NO GETDATE() IDX @CreateDateColumn Timestamp exacto del evento auditado. Se recomienda indexar esta columna para optimizar consultas de log por rango de fechas en SQL Server.
idUsuario INT — SÍ NULL FK → users.id Clave foránea al usuario que ejecutó la acción. NULL para operaciones de sistema no atribuibles a un usuario (ej: tareas programadas, migraciones). Relación ManyToOne con User.

Glosario de Tipos de Datos — SQL Server

INT — Entero
Número entero de 32 bits. Rango: −2,147,483,648 a 2,147,483,647. Usado en PKs e IDs con IDENTITY(1,1).
BIGINT — Entero Grande
Número entero de 64 bits. Rango: −9.2×10¹⁸ a 9.2×10¹⁸. Recomendado para tablas de alto volumen como logs de auditoría.
NVARCHAR(n) — Texto Unicode
Cadena de longitud variable con soporte Unicode completo (UTF-16). Reemplaza a VARCHAR para soportar caracteres como ñ, á, ü, etc.
NVARCHAR(MAX) — Texto Largo
Hasta 2 GB de datos de texto Unicode. Reemplaza el tipo TEXT deprecado en SQL Server 2005+. Usado en descripciones y campos JSON.
DECIMAL(18,2) — Monetario
Número de punto fijo con 18 dígitos totales y 2 decimales. Estándar del proyecto para cualquier valor monetario (salarios, presupuestos). Sin errores de punto flotante.
DATETIME2 — Fecha y Hora
Alta precisión (hasta 7 decimales en fracciones de segundo). Reemplaza a DATETIME y TIMESTAMP. Compatible con strings ISO 8601. Requerido por el proyecto.
BIT — Booleano
Almacena valores 0 (false) o 1 (true). Es el equivalente SQL Server al tipo BOOLEAN de PostgreSQL. Usado en campos como isActive.
IDENTITY(1,1) — Autoincremento
Propiedad SQL Server equivalente a AUTO_INCREMENT de MySQL. El primer parámetro es el valor inicial y el segundo el incremento. TypeORM lo aplica con @PrimaryGeneratedColumn('increment').
Código de Error 2627 / 2601
Violación de restricción UNIQUE en SQL Server. Equivale al código 23505 de PostgreSQL. El sistema los captura con error.number en handleDBExceptions.
Código de Error 547
Conflicto de clave foránea (REFERENCE constraint) en SQL Server. Se dispara al intentar eliminar un registro padre con hijos referenciados. Capturado para retornar mensajes amigables al cliente.
@AfterLoad — Hook TypeORM
Decorador que ejecuta un método automáticamente después de que TypeORM carga una entidad desde la base de datos. Usado para construir URLs completas de imágenes a partir del nombre de archivo guardado.
FK — Foreign Key
Restricción de clave foránea. Garantiza la integridad referencial entre tablas. En TypeORM se declara con @ManyToOne + @JoinColumn. La columna generada lleva el nombre definido en name.
